# M1.4d — Feed visual distinction baseline via styles.css 🟡


Intent:

- Improve immediate readability of the TaskX feed by clearly separating semantic
  line types (section headers, recommendation blocks, signals, rationale, and
  task lines).
- Reduce cognitive friction before policy-heavy sorting work in M1.5.

Constraint:

- This is a visual differentiation step, not a ranking or recommendation policy
  step.
- Styling must preserve existing stable DOM structure and class hooks.

Deliverables:

- Introduce or refine `src/styles.css` with explicit visual tokens for:
  - section titles,
  - recommendation containers,
  - signal badges,
  - rationale (`why`) lines,
  - task rows and provenance links.
- Ensure visual contrast makes signals and rationale clearly distinguishable.
- Keep styles deterministic and consistent across desktop and narrow layouts.

Implementation order (files to touch):

1. 🟡 `src/styles.css`
   - Add baseline visual system (colors, spacing, grouping contrast).

2. 🟡 `src/ui/feed/render-feed.ts` (only if class hooks are missing)
   - Add minimal stable class hooks required by style targets.

3. 🟡 `tests/contract/ui/feed/` and/or `tests/unit/ui/feed/`
   - Add/adjust DOM contract assertions for required class hooks only
     (no snapshot styling assertions).

Success criterion:

- In Obsidian, each feed line type is visually distinguishable at a glance.
- Signal badges and rationale text are no longer visually conflated.
- No ranking/grouping semantics are changed by this step.

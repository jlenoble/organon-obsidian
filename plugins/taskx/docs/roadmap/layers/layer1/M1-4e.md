# M1.4e — Inline task syntax spec (Tasks-compatible superset) 🟡


Intent:

- Replace opaque bracket-token metadata in TaskX spec tasks with a readable
  inline syntax based on emoji markers and explicit info tokens.
- Make TaskX inline tasks a strict superset of Obsidian Tasks conventions.
- Define a stable, auditable mapping between inline syntax and `TaskEntity`
  fields (including computed vs source-derived distinctions).

Constraint:

- Compatibility with existing Obsidian Tasks inline conventions is mandatory.
- TaskX-specific extensions must not break baseline Tasks interpretation.
- Mapping rules must state which fields are:
  - directly parsed from inline content,
  - computed from parsed content and context,
  - non-inferable without external context.

Deliverables:

- Add an exhaustive syntax spec document for TaskX inline tasks under `docs/`
  (single source of truth).
- Define baseline Tasks-compat coverage:
  - status markers,
  - dates,
  - priorities,
  - recurrence/dependencies conventions where applicable.
- Define TaskX extensions:
  - standalone emoji markers and emoji+info tokens,
  - token grammar, precedence, and collision handling.
- Define explicit field-level mapping:
  - inline token -> `TaskEntity` (or derived fact),
  - `TaskEntity` -> canonical inline representation (when reversible),
  - clearly marked non-1:1 cases.
- Plan migration path from bracket tokens to inline syntax for roadmap/spec task
  notes.

Implementation order (files to touch):

1. 🟡 `docs/` (new syntax spec file, e.g. `docs/taskx-inline-task-spec.md`)
   - Define grammar, token catalog, and compatibility scope.

2. 🟡 `docs/taskx-glossary.md` + `docs/taskx-naming.md`
   - Add stable names/ids for inline token families and mapping terms.

3. 🟡 `src/core/model/task.ts` and related model docs/comments
   - Align `TaskEntity` field documentation with source vs computed mapping.

4. 🟡 `src/adapters/obsidian/collect-tasks.ts` (and parsing utilities as needed)
   - Implement/align parsing with the approved inline syntax contract.

5. 🟡 `tests/` (T1)
   - Add parser and contract tests for Tasks compatibility + TaskX extensions.
   - Add round-trip/inference tests for mapped fields and non-1:1 cases.

Success criterion:

- TaskX inline syntax is documented exhaustively and unambiguously.
- Existing Tasks-compatible syntax remains valid.
- TaskX extension tokens are parseable and mapped consistently to model fields.
- Bracket-token metadata in active TaskX spec tasks can be migrated to the new
  inline syntax without semantic loss where mapping is defined.

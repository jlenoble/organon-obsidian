# M1.7 — Centralize tag-token helpers across collection and policy seams 🟡


Intent:

- Avoid duplicate ad-hoc tag parsing/matching logic as M1 introduces more
  tag-driven behavior.
- Keep tag token normalization semantics consistent across stages and adapters.

Constraint:

- This is a consolidation/refactor step at M1.x level, not part of M1.4c
  delivery itself.
- Behavioral semantics must remain unchanged during migration.

Deliverables:

- Introduce one shared helper module for tag-token normalization and matching.
- Define canonical behavior for:
  - optional leading `#`,
  - case normalization,
  - whitespace trimming.
- Replace local duplicated helpers in pipeline/entry paths with shared helper
  calls.
- Add focused unit tests for helper contract and edge cases.

Implementation order (files to touch):

1. 🟡 `src/core/model/` or `src/core/pipeline/` helper module (final location to
   be chosen by boundary fit)
   - Add shared normalization/matching primitives.

2. 🟡 `src/core/pipeline/stage-collect.ts` and related call sites
   - Replace local helper duplication with shared helper usage.

3. 🟡 Other tag-using M1 paths (as introduced)
   - Adopt shared helpers and remove ad-hoc variants.

4. 🟡 `tests/unit/`
   - Add deterministic helper tests and migration safety checks.

Success criterion:

- Tag token semantics are defined once and reused everywhere.
- No duplicated normalization logic remains in active M1 tag-driven code paths.
- Existing behavior remains stable after consolidation.
